# 丹青溢彩项目工作流

## 项目资产

丹青溢彩的核心资产是 `ComicProject`：

- `summary`：故事与画面目标，回答这部漫画讲什么、看点是什么、读者应获得什么情绪。
- `visualStyle`：画风与镜头，回答线条、色彩、角色造型、构图、镜头运动和一致性规则。
- `episodePlan`：海报构图规划或连载总规划，回答项目如何分章、分镜和持续出图。
- `assets`：素材库，包含人物、物品和场景。
- `chapters`：章节，每章有标题、章节内容简介、可选章节正文/故事内容、章节级提示、`storyboards` 分镜轨道、图片和素材引用。

Agent 不能把丹青溢彩当成单次图片生成器。它应把每次生成当成项目推进：补项目目标、补素材、拆章节、生成图片、审核一致性、写回状态。

## 用户交互模型

用户通常会这样使用：

1. 建一个漫画项目，写下类型、故事目标和画风。
2. 在素材库里维护主要人物、道具和场景。
3. 规划章节目录。
4. 选中一章，基于章节简介/正文拆成多条 `storyboards`。
5. 编辑每条分镜的画面、对白、镜头和生图提示词。
6. 对当前分镜生成单张图、漫画页、封面或连续图，并挂到该分镜。
7. 查看图片，修改分镜提示词或替换/追加当前分镜图片。
8. 根据成图继续完善下一章。

因此 Agent 输出必须贴近当前界面：

- 项目级结果写入 `summary / visualStyle / episodePlan`。
- 章节级结果写入 `title / summary / content / prompt / storyboards / status / assetRefs`，其中 `summary` 是章节内容简介，`content` 是可选正文或小说转漫画的故事文本，`prompt` 是章节级分镜提示，`storyboards` 是真正可出图的分镜轨道。
- 图片结果写入 `chapter.images`，并尽量通过 `storyboardId` 关联到当前分镜。
- 素材结果写入 `assets`，不要塞到章节备注里。

## 写回策略

默认策略：

- 讨论、审阅、构思：不写回。
- 用户说“帮我生成并替换/保存/写入/落到项目”：可以写回。
- 用户说“生成几张图放到这一章”：可以调用 `image_gen` 并用 `comic_update_chapter_images` 写回。
- 用户说“把这一章拆成 20 张分镜图”：先用 `comic_update_chapter` 写回 20 条 `storyboards`，再按当前分镜逐条出图。
- 用户说“完善人物素材/场景素材”：优先用 `comic_update_assets` 写回。

写回前应尽量读取最新项目并带上 `expectedProjectUpdatedAt`。

## 项目推进质量

好的漫画项目结果必须同时满足：

- 读者能看懂故事进展。
- 模型能生成稳定画面。
- 用户能在界面里继续编辑。
- 后续章节能复用素材和视觉约束。

差的结果包括：

- 只有抽象美术词，没有角色和动作。
- 只描述剧情，没有画面和镜头。
- 只生成图片，没有保留提示词。
- 只给“修改说明/保留取舍”，没有生成可编辑的 `storyboards`。
- 素材库和章节分镜/出图提示互相矛盾。
- 连续图每张都像独立插画，没有动作推进。
