# Writing

用于把小说创作从“直接写一段文本”收敛为可组合的长文本工作流。使用时先判断当前任务属于哪个节点，再按节点输入、输出和上下文依赖完成，不让模型自由漂移。

## 何时使用

| 场景 | 节点 |
|---|---|
| 从题材、主题、风格生成整本书方向 | `story_planner` |
| 调整已有书稿设定、调整主线但需要保留已有资产 | `story_rebuilder` |
| 需要补强时代、地图、制度、组织、规则、势力、怪物或战斗体系 | `world_builder` |
| 需要设计主角、配角、对手、关系与成长线 | `character_designer` |
| 需要判断下一章或下一阶段发生什么 | `plot_engine` |
| 需要规划一卷 / 一个大阶段的目标、压力、节奏、回收和阶段高潮 | `arc_planner` |
| 需要维护世界状态、角色状态、经济流动、主题锚点和不可逆后果 | `state_tracker` |
| 需要先拆本章问题、限制、信息差和代价 | `chapter_planner` |
| 需要把章节简介写成正文 | `chapter_writer` |
| 需要抽取新增事实、伏笔、时间线和规则 | `story_memory`（连续性资料更新） |
| 需要匹配番茄、晋江、轻小说、武侠等风格 | `style_controller` |
| 需要对白、高潮、战斗、反转或爽点强化 | `scene_specialist` |
| 需要按黄金一章/三章检查开篇追读力 | `opening_auditor` |
| 需要检查设定、人名、战力、时间线和伏笔 | `continuity_auditor` |

## 工作流

```text
story_planner
  -> story_rebuilder（已有书稿方向调整时插入）
  -> world_builder（先确认主角渴望与抵达方向，再补世界构成、地方路线、战斗、人物谱系、怪物生态网）
  -> character_designer
  -> plot_engine
  -> arc_planner（长篇 / 分卷 / 大阶段时插入）
  -> state_tracker（规划前读取，章节后更新）
  -> chapter_planner
  -> chapter_writer
  -> style_controller
  -> story_memory
  -> state_tracker
  -> opening_auditor
  -> continuity_auditor
```

## 全局状态协议

所有节点在进入规划或生成前，必须优先读取 `Genre Profile`、`storyAssets`、`narrativeState` 和已完成章节事实。

- `Genre Profile` 决定题材策略：探险/开荒强调地图、生态和地方活法；言情强调情绪递进和关系证据；悬疑强调信息差、线索和证据链；历史强调时代约束、社会结构和事件因果；都市/现实强调资源、身份、组织流程和关系博弈。不要把所有作品强行写成探险升级流、世界真相流或任务链。
- `storyAssets` 和 `narrativeState` 必须证据化更新。新增长期事实时，尽量写入 `evidenceRefs`（章节、正文短引、作者设定来源）和 `impact`（对后续章节、人物选择、资源、关系或伏笔的影响）。
- 人物成长必须沉淀为 `characterArcs`：`want` 是人物外在想要，`need` 是内在需要，`currentStage` 是当前阶段，`nextPressure` 是下一次推动变化的压力，`endpoint` 是长线终点方向。
- 技艺、武学、能力或生存判断的提升必须有铺垫链，不能写成“到一个地方 -> 遇一件事 -> 固定悟一招 / 升一级”的关卡奖励。
- 结局方向必须是人物、关系、技艺、路线和生活状态的自然收束，不得默认设计成揭穿终极阴谋、公布世界真相、击败最终 Boss、掌权成为天下之主或登顶成为天下第一。
- 禁止把“主角成长了、关系复杂了、世界更危险了”这类抽象判断当作资产；必须转成可验证的事件、证据载体、关系变化或后续影响。

## 创作提升准则

这些准则来自长篇奇幻 / 废土 / 冒险类项目的反复修订经验，适用于所有需要提升故事吸引力的小说任务。

### 探险故事先写渴望，不先写谜题

遇到末世探险、废土远行、雾后旅行、异境游历、奇观地图类故事时，主线默认从“主角主动靠近未知”出发，而不是从任务、阴谋或最终真相出发。先回答：

- 主角为什么想去看远方，为什么留在原地会让他痛苦。
- 他最想抵达哪里，那个地方承载什么童年经验、人生执念、自由欲或审美冲动。
- 家庭、制度、身体、资源、地貌或恐惧为什么曾经拦住他。
- 他第一次真正获得出走机会的具体事件是什么。
- 远行过程中，他每抵达一个地方，会第一次见到怎样的活法，并因此留下什么疑问、误判、限制、关系变化或延迟兑现的判断。

探险故事的主线优先是“抵达、见闻、选择和变化”，不是“揭露、收集、解锁和宣布”。除非作者明确要求，禁止默认设计：

- 世界真相驱动主线。
- 阴谋揭秘式推进。
- 最终 Boss。
- 主角拯救世界。
- 向群众公布真相式终局。
- RPG 式地图解锁。
- MMO 职业体系。
- 数值升级流。
- 任务链结构。
- 关键地图、地图碎片、宝图钥匙式道具。
- 直接套用书名或核心意象命名的关键物，例如“雾兆图”。

更优先使用零碎的人类痕迹推动探险：旧路人口述、残缺路歌、地方谚语、雾低时显字的路牌、死者鞋尖方向、桥木声音、潮汐习惯、交易暗号、灾后手艺和民间禁忌。它们是世界的生活痕迹，不是关卡钥匙。

地方感优先于地图感。设计地点时不要只写“资源点、势力、危险”，必须写“人为什么住在这里、怎么活、怎么称呼这里、有什么日常动作”。例如盐湖不是只产盐，而是盐潮上涨时人会拆门板、拴屋脚、夜里借倒星认路。

见闻感优先于主线说明。每一卷或每一大段应让主角第一次见到一种不同活法：有人靠卖影子活着，有人一辈子不离桥，有人替死人认路，有人记录从未存在的地名。群像通过短暂相逢、交易、互救、冲突和分道呈现，不默认组成固定小队。

偶然性是探险生命感的一部分。路线可以被雾暴、断桥、误听、救人、债务、地方节日、封路、怪物迁徙和天气改道打乱；但偶然进入后，人物选择和代价必须有因果。

战斗场面要绚丽、精彩、巧妙，但绚丽来自奇观地貌、光线、声音、怪物生态和工具连锁；精彩来自读者看懂主角如何观察、误导、借地形、借规矩、借生态反制；巧妙来自铺垫、限制和代价，不来自突然开挂或技能名轰炸。

故事内核应通过人物选择和地方秩序反思世界变化：让读者看见真诚、善意、勇气、守信、互救、敬畏自然等真善美如何在末世里仍有价值，也看见虚伪、掠夺、冷漠、交易化身体、滥用安全名义等假恶丑如何伤人。不要用作者议论替代场景。

### 作品成品必须纯净

书籍介绍、大纲指导、设定补充、章节简介、章节目录和正文都是作品设计文稿或作品文本，不是编辑过程记录。它们必须只呈现作品世界内部已经成立的设定、人物、路线、冲突、章节事件和风格边界。

模型可以在内部判断“保留、融合、降级、删除”，也可以参考作者聊天中的修改要求；但写入作品字段的成品不得暴露这些判断过程。尤其不能出现：

- “根据你的要求 / 按照上一版 / 这一版 / 旧版 / 新版 / 本次调整 / 修改建议 / review 建议 / 讨论上下文”。
- “不再使用 / 不加入 / 不写 / 不要 / 必须删除 / 必须降级 / 排除 / 被用户否定 / 用户明确要求”。
- “保留 / 融合 / 降级 / 删除 / 取舍判断 / 资产盘点 / 风险残留 / 待审备注”等内部审稿标签。
- “重构原则、资产保全、Schema、字段、工作流、节点、落盘、迭代记录、state_delta、storyAssets、Narrative State”等项目开发或状态管理语言。

需要表达边界时，必须转成正向作品设定语言：

- 把“不要写宫廷斗争”转成“王朝以军镇、关牒、粮道、供奉院等制度力量影响江湖”。
- 把“不加入妖鬼”转成“奇异感来自风雪、海潮、民俗、旧路、传闻与人心”。
- 把“删除旧追杀线”转成“主线从某人的行路、选择和关系余波展开”。
- 把“不能天下第一结局”转成“终局落在路线抵达、关系结算、技艺沉淀、地方余波或继续生活”。

审稿报告、内部计划和状态 JSON 可以使用工作流术语；一旦输出目标是作品字段，就必须先完成“内化”：只留下成品文本，不留下修改痕迹。

### 结局不是揭穿阴谋或登顶奖杯

长篇结局首先回答“主角如何带着一路经历继续活下去”，而不是回答“谁掌控天下”。除非作者明确要求，任何题材都不得默认使用以下终局机制：

- 揭穿一个覆盖全书的终极阴谋。
- 公布世界真相后完成大结局。
- 击败唯一最终 Boss 后世界恢复正常。
- 主角掌权、称王、成为天下之主。
- 主角成为公认天下第一或所有体系的最高裁判者。
- 以统一天下、建立新秩序、接管组织作为唯一满足感。

更优先的结局收束方式：

- **路程收束**：抵达某地或回到旧地，但主角对“抵达”的理解已改变。
- **技艺收束**：主角悟出一门武学、手艺或生存判断的真正用法，但它不是压服天下的万能答案。
- **关系收束**：还清一笔债、选择同行或分道、承认亏欠、保留某人的体面。
- **地方收束**：守住一个镇、一条路、一座桥、一门手艺或一群具体的人，让世界某处变得可继续生活。
- **价值收束**：主角不再被旧误信驱动，能在代价面前做出自己的选择。
- **余波收束**：旧问题关闭一部分，新生活仍有风险、未解之事和继续前行的空间。

武侠、玄幻、冒险和成长题材可以有高潮大战，但大战的意义应是“守住具体承诺、夺回行动自由、完成传承、保护一段路、让一个地方免于崩坏、让一段关系有结算”，而不是自动升级为天下排名或权力归属。主角可以变强，但不必成为最强；可以赢一战，但不必赢下天下；可以影响时代，但不必掌控时代。

规划 `ending_direction` 或角色 `endpoint` 时，必须写清：

- 主角最终放下或确认了什么。
- 主角保住、失去或改变了哪一件具体事。
- 哪些关系得到结算，哪些仍留有余味。
- 世界哪一处因主角行动产生可见变化。
- 主角之后会以什么姿态继续生活或继续上路。

### 技艺领悟不是关卡奖励

主角的武学、技艺、能力、战斗判断和生存经验可以提升，但提升必须像长期经验终于贯通，而不是像游戏通关结算。除非作者明确要求爽文式即时升级，不得默认使用：

- 每到一地固定悟出一招。
- 每遇一个地方事件就获得一个能力模块。
- 打完一场战斗立刻突破境界。
- 发现一个民俗、怪物弱点或旧物就直接解锁新技能。
- 用“他终于明白了”替代前文铺垫、误用和代价。

更自然的技艺领悟应具备一条可追踪的铺垫链：

1. **旧经验先失效**：主角原本会用的招式、判断或门派旧训在新环境里不完全适用。
2. **多次细小观察**：地方习惯、对手反制、身体伤势、失败战斗、旁人动作或旧游记细节反复出现。
3. **误用与代价**：主角先用错、用早、用狠、用得不合时宜，因此付出伤势、资源、关系或名声代价。
4. **关系或地方经验介入**：领悟不是凭空心理独白，而是被某个人、某种地方活法、某条路、某次失败或某个小物件触发。
5. **延迟兑现**：真正贯通可以晚于铺垫数章甚至一卷；当下事件可以只留下疑问、限制或未完成的手感。
6. **验证和余波**：领悟后必须在后续场景中证明它改变了行动方式，同时带来新限制、新责任或新代价。

技艺提升可以表现为：

- 更会收力，而不是更会杀人。
- 终于知道何时不用某招。
- 把前辈游记里的旧句子重新理解成身体经验。
- 把多个地方的见闻合成一种判断。
- 在关键时刻用更小的动作解决问题。
- 承认门派旧训只说对了一半，并为另一半承担后果。
- 把胜利目标从击败对手改成护住人、保住路、拖住时间或留下证据。

规划目录、章节或正文时，若安排主角领悟，必须写清“前文铺垫来自哪里、此前误用过什么、这次触发为什么恰到好处、领悟后带来什么限制”。如果没有足够铺垫，本章只能写成疑问、失败、观察、练习或半成的手感，不要直接突破。

### 已有书稿调整必须先盘点再融合

调整已有书稿时，不能把 `book.json`、`extraIntroSections`、`storyAssets`、`mapAtlas`、`worldOrganizations`、`monsterSystem`、`combatSystem`、`characterLineage / relationships`、`chapters.json` 整块覆盖成新方向。必须先做资产盘点：

- 必须保留：用户明确要求保留的设定、人物谱系、地图台账、组织关系、怪物体系、战斗体系、伏笔和连续性资料。
- 必须降级：与新方向冲突但仍有价值的旧设定，改成地方传闻、旧名、民间误解、历史残留、黑市行话或后续待定项。
- 可以删除：重复、模板化、已被用户否定、无法服务人物/地图/冲突的空设定。
- 必须同步：若清空章节规划，只能清 `chapters.json` 和章节正文映射；世界设定资产仍要保留或融合，不得随章节一起清空。

内部调整计划必须明确列出“保留 / 融合 / 降级 / 删除”四类处理结果。若无法确认某项是否该删，默认保留为待审备注。

如果最终输出会写入 `intro / outlineGuide / extraIntroSections / chapters.summary / storyAssets / narrativeState` 等作品字段，则不要把上述四类处理结果写进成品；必须把它们消化成正向设定稿、目录稿或结构化事实。用户明确要求“总结修改过程 / 给 review 看 / 输出审稿报告”时，才可以展示处理清单。

### 设定必须转化为章节发动机

有逻辑的设定只是起点，不能停在概念解释。每条核心设定都要能转化为：

- 一个角色当下的渴望、抵达目标或必须解决的行动难题。
- 一个阻止目标的资源、规则、地理或势力障碍。
- 一个可视化场景或行动难题。
- 一个胜利后的具体收获、代价、敌意或新问题。

如果设定无法推动抵达、见闻、冲突、选择或后果，应压缩为背景，不要扩写成说明段。

### 故事推进总纲

所有世界、人物、生态、路线、组织、怪物和规则，最终都必须持续压迫主角做选择。若一个设定不能改变行动、代价、关系、身份、资源、情绪或价值判断，则它只能作为背景存在，不得长期占据正文。

### 剧情优先级裁剪原则

任何设定在扩写前，必须回答：

- 是否影响主角当前阶段的行动。
- 是否影响最近 3-5 章冲突。
- 是否影响资源、路线、身份、关系或代价。
- 是否会在未来明确回收。

若不能影响近期剧情推进，只允许保留一句摘要，不展开详细设计。长篇世界允许存在未展开区域，但禁止提前完整建库；不要为了世界很大而把地图、怪物、组织、经济和习俗全部一次性写满。

### 信息释放原则

正文一次只允许读者真正记住少量新增信息：1 个新规则、1 个新地点、1-2 个关键人物、1 个新危险、1 个核心情绪目标。超过后，其余内容必须降级为背景感知。

设定不能按百科顺序释放，必须绑定行动、危险、误判、交易、失败或关系变化。读者先看见角色为什么必须理解这个规则，再接受规则本身。

### 不可逆后果原则

重要冲突后，至少一个条件必须永久改变：地点损毁、路线封闭、势力态度改变、身份暴露、身体残缺、资源断供、名声固化、怪物生态改变、关系无法恢复或某条规则被公开。世界必须记得人物做过什么。

### 叙事压缩原则

连续三章若未发生地图变化、关系变化、身份变化、资源变化、规则变化或世界状态变化，则必须压缩、合并或跳过过程。长篇允许留白，不要求完整模拟每天生活；日常片段必须承担关系、气氛、伏笔或代价功能。

### 人类压力优先原则

大多数长期冲突，本质来自人与人、制度与人、资源与人、关系与人、生存价码与人。怪物更多负责放大压力、改变路线、制造环境、扭曲经济和改变地方活法。不要让故事长期退化为“进入新地区 -> 打新怪”。

### 浅层刺激和深层反思必须同场出现

长篇不能只靠深刻，也不能只靠热闹。优先让读者先读到浅层刺激：逃生、探险、怪物、交易、追杀、反杀、奇观穿越、身份变化；再把深层反思藏进制度、资源分配、命名、价码、阶层、地缘关系和角色选择里。不要用作者议论替代剧情压力。

### 故事补充的设计顺序

需要系统补强设定时，默认按以下顺序推进。这个顺序适用于长篇、游历、多势力、奇幻、玄幻、废土、异能都市、科幻、战争、冒险和成长战斗类项目；普通现实题材也可缩小尺度使用。不是每本书都必须写满七项，但只要涉及对应内容，就应按顺序补齐，不要先堆角色、能力或怪物，再回头临时拼世界。

1. **主角渴望与出发理由**：先说明主角为什么想靠近未知、想抵达哪里、为什么过去不能走、现在为什么有了机会。探险故事尤其要先建立“我想去看看”的主动性，不要让主角被地图、任务或谜题推着走。
2. **世界构成总设**：说明这是一个什么样的世界。必须按题材需要交代人种 / 物种 / 生物类型、领导力量与社会组织、主要阵营、资源与法律、力量体系或技术体系。西幻可有人类、矮人、精灵、兽人和王国 / 教会 / 法师塔；东方玄幻可有人族、妖族、宗门、王朝、法术、法宝和傀儡；异能都市可有人类、变种人、官方机构、地下组织和异能来源；普通战斗题材也要说明社会秩序、训练体系、武器和组织。
3. **路线与地方台账**：再把世界落到可抵达的地方。按故事尺度设计宇宙 / 星球 / 大陆 / 国家 / 城市 / 村镇 / 建筑 / 路线层级；明确区域划分、范围、相邻关系、路线成本、地形环境、资源点、控制势力和地缘政治。每个地点还必须写出当地人为什么住在这里、怎么生活、怎么称呼危险、如何利用奇观。
4. **战斗与生存体系**：如果故事有成长、战斗、冒险、战争、异能、修行或职业冲突，必须单独补战斗方式和战力评比。先说明战斗目标、能力来源、训练方式、装备材料、生存工种、资源消耗、反制规则、失败后果、战力阶梯和社会身份，不要只写“谁更强”。战斗不只为杀敌，还可以拖时间、夺路、护送、断后、封门、引怪、保住证据或换取通行权。
5. **主角人生轨迹**：设计主角从出生 / 前史到故事终局的时间线。必须按时间排序写清重要经历、创伤、训练、关系、身份变化、能力变化、价值观变化、关键失败、关键胜利和最终归宿。主角轨迹要贯穿路线、组织、力量体系和主线渴望。
6. **角色谱系档案**：再设计全书配角、对手、导师、同行、制度人物、亲缘人物、非人角色等人物谱系。每个重要角色都要有身份、性格、能力 / 资源、命名来源、人生经历、成长节点、与主角的交集、生活惯性、人物气味、地方化身体习惯、关系小证据、留白、秘密、债务和结局方向。不是“他是谁”就结束，而是说明他如何像一个原本就活在这个世界里的人，并在必要时改变局势。
7. **怪物生态圈**：如果有怪物、妖兽、异族、非人生物、灾变生物、异星生物或类人文明，必须单独补生态圈。先写生态发动机、物种谱系、食物网、尺度 / 栖境 / 体态矩阵、栖息地、食物、繁殖、迁徙、天敌、共生、社会结构、能力来源、人类关系、资源价值和反制方法，再写战斗用途。怪物命名必须有人文、地域、生态、职业或交易来源，不要批量套同一字头或同一后缀；除非题材明确是虫灾、蛛巢或菌变，否则虫、蛛、菌等形态不能成为主要想象来源。

输出时建议把这些内容写成稳定台账：`protagonistDesire`（主角渴望与出发理由）、`worldComposition`（世界构成总设）、`mapAtlas`（路线与地方台账）、`combatSystem`（战斗与生存体系）、`protagonistTrajectory`（主角人生轨迹）、`characterLineage / characters`（角色谱系档案）、`monsterSystem`（怪物生态圈）。如果项目存储结构暂未支持某字段，可先写入 `storyAssets.worldview / rules / relationships / memoryNotes / extraIntroSections`，但要保留这些名称，方便后续迁移。

### 路线与地方感的长篇规划

涉及大地图、远征、势力边界或奇观探险时，`world_builder` 应在确认主角为什么出发后建立路线与地方台账：

```json
{
  "mapAtlas": {
    "coordinateSystem": {
      "origin": "",
      "unit": "",
      "axes": {},
      "narrativeUse": ""
    },
    "regions": [
      {
        "id": "",
        "name": "",
        "type": "",
        "center": { "x": 0, "y": 0, "z": 0 },
        "bounds": {},
        "coverage": "",
        "features": [],
        "resources": [],
        "monsters": [],
        "factions": [],
        "neighbors": [],
        "geopoliticalRole": "",
        "storyFunction": ""
      }
    ],
    "routes": [],
    "geopoliticalRelations": []
  }
}
```

坐标用于创作规划，不应机械写进正文。正文要写方向、路程感、地貌过渡、势力边界、地方生活和角色判断。

### 奇观地图必须绑定生态、代价与长期领悟

每处奇观至少需要六项绑定：视觉记忆点、可争夺资源、怪物生态、人类利用方式、地方日常习惯、主角可带走的疑问 / 限制 / 误判修正 / 迟到领悟线索。奇观不能只是漂亮地名，也不能成为“到站奖励”；它必须改变路线、视野、战斗方式、交易规则、资源分布或人物关系。不是每处奇观都要让主角立刻变强，有些地方只负责让旧经验失效、让旧游记变得可疑、让主角第一次意识到自己还不会。

### 怪物体系必须像生态网而不是怪物清单

怪物设计优先参考真实动物体系，再加入奇幻变异。每个怪物群落至少考虑：

- 生态发动机：光、热、雾、盐、尸体、矿尘、菌毯或旧能源如何养活这个地区。
- 物种谱系：共同起源、共同压力或共同栖息地形成的类群，而不是互不相关的单体怪物。
- 尺度矩阵：微型、小型、中型、大型、巨型 / 超大型、地貌级 / 群体级生命如何共同构成生态，不要只有“小怪 + 中怪”。
- 栖境矩阵：陆地、水域、空域、地下、建筑寄生、植物冠层、雾域、类人社会如何分布，不要只有地面遭遇。
- 体态矩阵：哺乳、鸟、鱼、软体、爬行 / 两栖、植物、矿物、气雾、群体、类人等形态如何组合，不要让虫、蛛、菌占主导。
- 栖息地和食物来源。
- 食物网关系：吃谁、被谁吃、与谁竞争、寄生谁、与谁共生、死后养活谁。
- 繁殖、护崽、迁徙、争水、筑巢、捕猎或共生行为。
- 底层清道 / 滤食者、中层领地 / 迁徙者、上层异常 / 巨型节点 / 类人社会。
- 与人类资源、路线、制度或禁忌的冲突。
- 怪物自己的社会意识、等级、工种、交易或族群目的。

不要把怪物写成只会嘶吼、扑咬、肌肉大、利爪锋利的敌兵。
不要只列 5-10 个危险物种。每个核心地区至少要能看见基底生产者、清道 / 分解者、小型群居物、牧食 / 滤食者、中型捕食者、寄生 / 拟态者、生态工程者和关键种。全书层面还应看见空中、水中、地下、建筑中、地貌级和类人社会的生命。只有少数物种需要正面战斗，其余物种也应通过痕迹、材料、季节、价格、方言和职业习惯让世界变厚。

### 怪物必须长成生存民俗

怪物、异兽、灾变生物和非人文明不应首先作为“战斗单位”登场。设计时先回答“一个地方的人如何长期活在这种生物附近”，再决定它能否战斗。禁止只按“一个功能 + 一个地形 + 一个弱点”生成怪物；这会让故事变成副本机制或怪物图鉴。

每个重要怪物至少要补出：

- 人们如何误解它，哪些谣言是错的，哪些经验彼此矛盾。
- 孩子如何害怕它，老人如何讲它，商队如何绕开它。
- 哪些职业依赖它、利用它、猎杀它或因它形成行业禁忌。
- 哪些日常习惯、仪式、丧葬、节日、偏方、黑市造假或交易称呼因它出现。
- 它如何改变地方语言、方言、骂人话、避讳名、路歌或暗号。
- 人类对它的情感关系：恐惧、敬畏、崇拜、模仿、利用、怀念、牟利或怜悯。
- 它登场时的诗意和不可完全理解之处：哀伤、荒凉、奇异美感、像天气一样的压迫，而不只是危险参数。

怪物知识必须允许不完整和有争议。当地人可以知道有效偏方，却说错原因；行会可以争论该熄灯还是点灯；官方称呼、民间俗名、猎人黑话和怪物自称可以彼此冲突。正文中优先写生活痕迹：桥工听桥腹里的潮鸣，档案馆在纸页里夹盐叶，船夫怕盐湖上的第二道影子，孩子被教导不要隔雾喊真名。战斗要建立在这些经验、误解和禁忌之上，而不是靠百科式弱点说明。

### 战斗体系必须从生存方式长出来

战斗不是凭空出现的能力对轰。设计战斗体系时，先问这个世界为什么必须战斗：争资源、争路线、争安全区、争社会地位、争命名权、争生存资格。再按生存工种拆分能力、装备和战术，例如修桥、背灯、听潮、验尸、缝肺、驱兽、记路、运盐、清障或谈价；这些人只是因为环境危险，才自然具备战斗能力。不要把职能写成固定职业树或固定小队配置。

战斗场面必须同时管理合理性和读者体验：空间要动态变化，时间要形成压力，感官要压迫判断，错误要有代价，对手要会学习或反制，失败也要改变后续世界状态。每场战斗结束后都应至少改变一种条件：路线、资源、关系、身份、名声、债务、规则理解、地方秩序或人物价值观。

### 命名必须有人文来源

保留核心意象即可，不要让所有职业、道具、怪物和地点都套同一个字头。命名应来自历史、地理、职业、俗称、官称、技术名、禁忌名、族群语言或交易称呼。同一事物可因群体不同拥有多个名字。

### 人物谱系先于人物表

长篇人物设计不能只列姓名、身份和性格标签。先建立人物谱系，再补角色档案。谱系的作用是说明一组人物共同承担什么叙事功能，例如：

- 血缘 / 前史线：解释主角性格来源、旧伤、旧物和后续选择。
- 同行 / 伙伴线：测试信任边界、资源交换、救急与背叛。
- 制度 / 城市线：把抽象规则变成人、账册、牌照、债务和权力。
- 对手 / 压制线：建立被低估、被利用、被定价和反夺价码的结构。
- 技术 / 职业线：让战斗体系、旧械、医救、斥候、交易等职能人格化。
- 非人 / 文明线：让怪物社会拥有工种、阶层、交易、禁忌和族群目的。

每个重要角色必须像主角不在时也会继续生活。角色不是设定集合，也不是单纯剧情工具；他应长期活在某种地方、关系、制度、痛苦或希望里，并留下习惯、偏见、动作、口头禅、规避方式、羞耻、怀念、小聪明和不愿被提起的东西。

重要角色通常要能改变至少一种状态：主角目标、资源、关系、身份、信息差、地图可达性、规则理解或代价。若不直接推动剧情，也必须提供明确的地方感、生活感、情绪停顿、价值对照或世界真实度。不能只负责夸主角、解释设定、临时送道具或制造一次性情绪。

角色档案中的目标、恐惧、秘密和债务不能停在标签，应转成行为痕迹：睡觉靠墙、分钱先留船票、讲话前看门、不踩盐裂、听见木梁响就抬头。关系推进也不能只靠大事件和旁白宣布，要有共同无聊时间、共享小资源、目睹脆弱、没有揭穿、替对方保留体面等小证据。重要角色不应一次性解释完，需保留传闻、旧物、矛盾证词或不愿解释的习惯，让读者逐步拼出这个人。

人物谱系不是可选补充。凡是长篇、游历、多城镇、多组织、多怪物、多阵营、复仇、远征或人生执念结构，在完成主角渴望、世界构成、路线地方、必要战斗体系和主角人生轨迹后，必须建立人物谱系和关键经历，再进入章节规划和正文。人物经历要成为串联地方、组织、伏笔和战斗的线，而不是设定完成后的附录。

## 节点约定

### story_planner

输入：`genre`、`theme`、`style`、`length`、作者额外要求。

输出必须结构化：

```json
{
  "premise": "",
  "main_plot": "",
  "core_conflict": "",
  "emotional_promise": "",
  "ending_direction": "",
  "chapter_strategy": ""
}
```

额外要求：

- 必须明确浅层读感承诺和深层主题承诺，避免只写题材标签。
- 必须说明主角成长的可见沉淀：生存、资源、能力边界、身份、关系或价值选择如何逐步改变；技艺领悟要有铺垫、误用、代价和延迟兑现，不写成地点结算奖励。
- 必须把 `ending_direction` 写成自然收束方向：人物归宿、关系结算、技艺领悟、路线抵达、地方余波或价值选择，不写成默认揭阴谋、称王、统一天下或天下第一。
- 必须把故事介绍写成“为什么读者要继续看”的承诺，而不是世界观百科。

### story_rebuilder

用于已有书稿的方向调整、世界观改造、章节清空前的资产保护、旧设定合并与降级。

开始前必须读取当前 `book.json`、`chapters.json`、已有章节正文清单，并按任务读取 `references/continuity-auditor.md` 以及地图、组织、人物、怪物、战斗相关参考。先在内部形成资产处理计划：

```json
{
  "preserve": [],
  "merge": [],
  "downgrade": [],
  "delete": [],
  "missing_assets_to_restore": [],
  "next_design_tasks": []
}
```

对外输出分两类：

- 若作者要求的是“检查 / review / 说明怎么改”，可以展示资产处理计划。
- 若作者要求的是“重写大纲 / 修改小说配置 / 生成设定稿 / 更新作品资料”，最终只输出可直接写入作品的纯净成稿，不展示资产处理计划、修改说明或旧方案对比。

额外要求：

- 调整主线时，先盘点已有世界构成、路线地方、组织、怪物、战斗与人物资产；重新设计时按故事补充的设计顺序推进，并特别补齐主角渴望、主角人生轨迹、人物谱系和关键经历。
- 简化世界时，只能降低设定显性程度，不能删除支撑长篇连续性的台账。
- 清空章节规划时，不等于清空世界设定；目录、正文、设定资产分别处理。
- 若用户要求“以丰富世界背景和设定为主”，不得生成章节目录，只维护创作圣经、主角渴望、路线地方、组织、人物、怪物、战斗、规则和待办。

### world_builder

输出世界规则、资源、禁忌、阶层、势力、代价、地方生活和冲突源。世界观必须能驱动剧情，不能只列名词。

推荐输出：

```json
{
  "protagonistDesire": {
    "longing": "",
    "destination": "",
    "whyNotStay": "",
    "firstChanceToLeave": "",
    "innerChangePromise": ""
  },
  "worldComposition": {
    "speciesOrPeoples": [],
    "leadershipForces": [],
    "socialOrders": [],
    "resourceSystems": [],
    "powerSystems": [],
    "technologyOrCrafts": [],
    "conflictPattern": ""
  },
  "worldview": [],
  "rules": [],
  "factions": [],
  "worldOrganizations": [],
  "mapAtlas": {},
  "monsterSystem": {},
  "combatSystem": {},
  "protagonistTrajectory": [],
  "characterLineage": [],
  "taboos": [],
  "conflict_sources": [],
  "travelWitnesses": []
}
```

额外要求：

- 系统补设定时，先按“主角渴望与出发理由 -> 世界构成总设 -> 路线与地方台账 -> 战斗与生存体系 -> 主角人生轨迹 -> 角色谱系档案 -> 怪物生态圈”推进；不得先堆角色名单、能力名或怪物名，再临时解释世界。
- 世界构成总设必须交代本题材实际存在的人种 / 物种 / 生物类型、领导力量、组织形态、资源秩序和力量 / 技术体系；没有的内容明确写“本书不使用”，不要留空制造误读。
- 大地图项目必须在主角渴望成立后确认地理方位、覆盖范围、相邻区域、路程成本、地方生活和地缘关系。
- 涉及星球、洲洋、国家、城市、村镇、家宅、建筑或路线设计时，先读 `references/story-map-design.md`。
- 涉及国家、政权、宗门、公司、教会、军队、学院、行会、秘密组织或大型社会制度时，必须先读 `references/world-organization.md`。
- 涉及怪物、异兽、异族、类人怪物、怪物材料或怪物命名时，必须先读 `references/monster-system.md`。
- 涉及战斗体系、能力体系、生存工种、战力成长、失败后果、战斗审美或人怪 / 人人冲突规则时，必须先读 `references/combat-system.md`。
- 涉及长篇、游历、多势力、复仇、远征或人生执念主线时，必须同步建立人物谱系；路线地方、组织关系、怪物和战斗都要能挂回人物经历。
- 怪物、能力、资源和势力必须绑定具体地貌或社会结构，不要孤立造词。
- 世界冲突应能落到章节行动，例如取水、过桥、进城、守路、交易、撤离、狩猎、证明身份，也要落到一处地方的一种活法。

```json
      "rules": []
    }
  ],
  "characters": [
    {

      "lineage": "",
      "role": "",

      "goal": "",

      "relationships": [],
```

额外要求：

- 涉及人物谱系、角色档案、角色关系或长篇多人物规划时，先读 `references/character-lineage.md`。
- 先写主角人生轨迹，再展开配角谱系；主角轨迹要按时间排序贯穿前史、开篇、中段、高潮和终局，不要只写“成长为更强的人”。
- 先按谱系组织人物，再扩展单个角色；不要让角色以散点名单方式堆在设定里。
- 每个角色档案必须区分“公开身份、隐秘信息、叙事功能、对主角施加的压力、可回收证据”，并补出日常生活、习惯动作、地方身体记忆、正在忍受的问题和不愿解释的过去。
- 角色命名必须有地域、阶层、家族、职业、时代或族群来源，并区分本名、外号、官称、代号、禁忌名和关系称呼。
- 每条谱系至少有一条关系推进规则，例如“有限同行不能突然变成无条件同伴”“制度人物不靠暴躁作恶，而靠平静称量人”。
- 重要角色第一次出场必须带动作任务、资源、冲突或自己的生活难题，不要用履历介绍开场。
- 关系变化要有小证据：没拆穿、递半块饼、默认留座、替对方保留体面、危险结束后仍给对方留退路。
- 重要角色需要留白；不要在第一次出场就把目标、恐惧、秘密、创伤和结局方向全部解释完。
- 如果当前存储结构没有独立 `characterLineage` 字段，可把谱系写入 `storyAssets.relationships / worldview / memoryNotes`，把单人档案写入 `storyAssets.characters`。

### plot_engine

只负责决定下一阶段怎么推进，不直接写正文。长篇、多卷、多地区或连续推进超过 8-10 章时，必须把结果交给 `arc_planner` 做阶段结构，不直接跳到章节级规划。

推荐输出：

```json
{
  "next_conflict": "",
  "twist": "",
  "emotion_goal": "",
  "chapter_target": "",
  "character_shift": "",
  "foreshadow_action": ""
}
```

额外要求：

- 每一阶段都要同时推进抵达方向、地图位置、资源状态、敌我关系和主角成长。
- 避免连续使用“观察 -> 遇险 -> 脱困 -> 继续走”的同质节拍；要轮换追逃、夺物、误判、反杀、谈价、交易、探索、规则战和关系撕裂。
- 阶段推进应让故事渐入佳境：新地方带来新活法，新规则逼出新战斗方式，新战斗方式改变主角身份或价值判断。
- 输出前先读 `references/narrative-control.md`，检查阶段设定是否影响最近 3-5 章；若只是扩世界，应裁剪为一句背景。

### arc_planner

用于长篇的一卷、一个大阶段、一次远行区段或 8-30 章左右的阶段规划，插在 `plot_engine` 与 `chapter_planner` 之间。复杂任务先读 `references/arc-planner.md` 与 `references/narrative-control.md`。

推荐输出：

```json
{
  "arc_goal": "",
  "arc_false_goal": "",
  "arc_new_region": "",
  "arc_pressure": "",
  "arc_relationship_shift": "",
  "arc_cost": "",
  "arc_payoff": "",
  "arc_end_reversal": "",
  "chapter_range": "",
  "state_changes": []
}
```

额外要求：

- 每一卷 / 阶段必须有阶段目标、阶段假目标、阶段压力、关系位移、不可逆代价、阶段回收和结尾反转。
- 阶段目标必须能拆成章节目标；章节目标必须回扣阶段目标，避免每章都像中间章。
- 阶段不能只换地图或换怪物，必须改变主角身份、关系、资源、规则理解或价值判断。
- 阶段成长不要求每卷结算一次新招式或境界；可以只推进观察、误用、失败、训练、手感和限制，等铺垫成熟后再水到渠成地贯通。
- 阶段收束要给读者满足感：至少回收一个承诺，关闭一个旧问题，同时打开一个更高层级的新问题。
- 终局阶段不得默认收束为揭穿终极阴谋、登顶、掌权或建立新秩序；优先收束为具体承诺兑现、人物误信改变、关系清账、路线抵达、技艺领悟和带余波的新生活。

### chapter_planner

只负责把当前章节目录和上下文拆成可执行计划，不直接写正文。必须明确本章核心问题、场景顺序、主角目标、阻碍、规则/资源/时间限制、信息差、对手反制、证据载体、代价、人物变化、伏笔/回收和结尾钩子。

推荐输出：

```json
{
  "chapter_problem": "",
  "scene_order": [],
  "constraints": [],
  "information_gap": "",
  "opponent_countermove": "",
  "evidence_carrier": "",
  "cost": "",
  "ending_hook": ""
}
```

额外要求：

- 章节计划必须先回答：本章主角想拿到什么，谁或什么阻止，危险的第二层是什么，赢的证据是什么，代价是什么，为什么下一章必须继续读。
- 若章节有人物出场，必须确认每个出场人物所属谱系、当前关系状态、本章施加的压力和离场后的状态变化。
- 若章节发生在地图型世界，必须确认当前位置、目标位置、相邻路线、控制势力、地方生活和地貌过渡。
- 若章节出现怪物，必须写出至少一个动物性行为和一个世界观能力行为。
- 规划前读取 `state_tracker` 的当前状态：时间、伤势、资源、路线、组织态度、价格、迁徙和主题锚点；本章结束时必须说明状态差异。
- 本章新增设定不得超过信息释放原则；若需要新规则、新地点、新人物、新危险同时出现，必须明确哪些降级为背景感知。

### chapter_writer

只把确定的章节目标写成正文。必须遵守当前章节职责、人物状态、世界规则和风格约束。正文按“问题 -> 规则/资源限制 -> 信息博弈 -> 对手反制 -> 主角选择 -> 代价/新证据 -> 余波或悬念”推进；正文开头不带章节标题。

额外要求：

- 正文优先写具体行动、触感、方位、资源消耗和选择后果，不用抽象形容词替代场景。
- 热血来自明知代价仍做选择，不来自口号；深刻来自制度和资源压力，不来自旁白说理。
- 每章至少让一个状态发生变化：位置、资源、伤势、关系、身份、情报、敌意、规则理解或地图可达性。
- 连续三章如果没有状态变化，必须压缩或合并过程。
- 冲突后至少保留一个不可逆后果，不让伤势、路线、名声、价格、关系和组织反应自动复原。

```json
    "relationships": [],
    "worldOrganizations": [],
    "mapAtlas": {},
    "monsterSystem": {},
    "combatSystem": {},
    "world_state": {},
    "character_state": [],
    "economicFlows": {},
    "themeAnchors": [],
    "irreversibleConsequences": [],
    "timeline": [],
    "foreshadows": [],
    "rules": [],

```

只记录后续章节必须遵守或可回收的事实，不收录一次性辞藻。`story_memory`、`memoryNotes` 和连续性资料都是内部管理概念，不应被扩写成作品主题、主角能力或世界观机制。

人物资料更新时额外注意：

- 新角色进入主线后必须补 `role / goal / fear / secret / growthArc / relationships / tags / status`。
- 谱系规则优先写入 `relationships` 或 `memoryNotes`，例如“药棚善意必须有账”“下庭怪物会交易而不是只嘶吼”。
- 角色状态变化要可追踪：信任升降、债务新增、秘密暴露、资源损耗、身份改变、阵营摇摆。
- 对死者、失散者、记忆人物、非人角色要明确 `status`，避免后续章节误当普通在场角色使用。
- 章节后必须记录至少一个状态差异；若确实没有状态差异，应标注该章可被压缩、合并或作为低权重过渡章。

### style_controller

根据目标风格调整叙事密度、句式、声口、爽点、情绪距离和类型期待。风格控制不能破坏既有事实；复杂风格任务先读 `references/style-controller.md`。

### scene_specialist

用于对白、战斗、高潮、打脸、反转、追逃、告白、审判等高张力场景。场面必须有空间调度、信息差、代价和余波；复杂场面先读 `references/scene-specialist.md`。若任务不是单场打斗润色，而是要设计战斗体系、职业能力、战力成长或反制规则，同时读取 `references/combat-system.md`。

### opening_auditor

检查第一章和前三章的商业追读力。开篇首先必须是一个顺畅、具体、能读下去的小故事，再承载世界观、主线伏笔和卖点展示。审核维度包括故事通顺度、主角聚焦度、类型/背景清晰度、卖点或金手指吸引力、追读期待、新颖差异化、信息密度和低级错误风险。必须额外检查六类雷区：开场拥挤、人物过多、群像开局、设定倾倒、环境堆砌、人物白描。输出必须给评分、证据、最小修法和可直接替换片段。

### continuity_auditor

检查人名、关系、动机、时间线、地点、能力边界、世界规则、伏笔账本和视角声口。输出问题必须带最小修复方案；长篇或多章节审核先读 `references/continuity-auditor.md`。

## 输出原则

- 能结构化就结构化，目录、章内计划、连续性资料和审核优先 JSON。
- 生成和修订分离，先完成可推进版本，再把需回头处理的内容写入设定账本。
- 已有书稿调整时，默认增量合并，不默认整块替换；除非用户明确要求删除某类资产，否则先保留并标注为“待审 / 降级 / 暂停使用”。
- 章节规划、章节正文和世界设定是三类资产：清空章节不等于删除设定，调整主线不等于删除地图、组织、人物、怪物和战斗台账。
- 生成类任务先内部自评再输出；只有体检、质检、审核类任务才显式输出评分和问题表。
- 作者约束和 AI 台账分离，作者要求优先；AI 维护的连续性资料只记录事实、信息差、证据载体、伏笔和规则边界。
- 开篇优先单主角、单事件、单视角、单冲突，首场命名人物建议小于等于 3 人；长篇可以群像长线，但不建议群像开局。
- 开篇设定必须剧情化释放，环境描写必须服务事件，人物介绍必须通过行动和选择显形。
- 长篇只看局部上下文会崩线，必须同时参考创作圣经、结构化故事资产、最近章节和后续承接。
- 关键转折必须有证据载体，避免用抽象顿悟替代剧情变化；对手或环境必须反制，避免主角一路顺畅。
- 风格可以变化，事实不能漂移。
- 专业写作助手应描述精准简练，少用“精彩、丰富、宏大、逐渐、命运、真正、某种意义上”等空泛词，除非它们被具体场景、行动或后果支撑。
- 遇到用户批评“无聊、口水化、AI 味、没有吸引力”时，优先回到主角渴望、抵达方向、地方感、见闻感、资源、怪物生态、战斗体系、成长阶梯和章节钩子重构，不只做文风润色。
- 遇到角色单薄、人物散乱或长篇后续难接时，优先建立人物谱系和角色档案：先判断角色属于哪条线、给主角什么压力、改变什么状态，再决定是否需要出场。
