# Continuity Auditor Reference

`continuity_auditor` 负责保护长篇的可信度。审核目标不是挑文采，而是找出会让读者出戏、让后续剧情无法承接的矛盾，并给出最小修复方案。

## 审核输入

优先同时读取：

- 创作圣经：题材、主题、主线、结局方向、类型承诺。
- `storyAssets`：世界观、人物、关系、时间线、伏笔、规则、风格档案。
- 最近 5-10 章摘要或正文片段。
- 当前章节目标、章节正文、后续承接要求。

信息不足时，明确标注“无法确认”，不要把推测当成错误。

## 检查矩阵

| 类别 | 检查点 |
|---|---|
| 已有内容保留 | 方向调整前后的 `extraIntroSections / storyAssets / mapAtlas / worldOrganizations / monsterSystem / combatSystem / characterLineage / chapters` 是否被误删、误覆盖或丢失 |
| 身份与命名 | 人名、称谓、年龄、身份、门派、职位、物品名是否前后一致 |
| 时间线 | 昼夜、日期、旅程耗时、伤势恢复、事件先后是否能成立 |
| 地理与空间 | 角色位置、距离、路线、场景进出和战斗方位是否自洽 |
| 地图台账 | 区域坐标、覆盖范围、相邻关系、控制势力、路程成本和章节路线是否一致 |
| 世界组织 | 国家、城邦、宗门、公司、教会、军队、学院、行会等组织的权力边界、称呼、制度、派系和反制是否一致 |
| 能力与规则 | 境界、技能冷却、代价、资源消耗、禁忌是否遵守 |
| 怪物生态 | 怪物栖息地、食物来源、繁殖迁徙、社会等级、能力和资源冲突是否能成立 |
| 战斗职能 | 战斗目的、生存工种、能力边界、动态空间、时间压力、错误代价、反制关系、失败后果和胜负证据是否清楚 |
| 人物谱系 | 角色所属谱系、叙事必要性、生活惯性、关系状态、秘密暴露和出场职责是否清楚 |
| 关系状态 | 亲疏、敌友、秘密暴露程度、误会是否被提前消除 |
| 动机与选择 | 角色行动是否符合目标、恐惧、利益、价值观和已知信息 |
| 因果链 | 结果是否有足够铺垫，关键转折是否凭空发生 |
| 伏笔账本 | 已埋伏笔是否记录，回收是否对应，是否遗忘重要承诺 |
| 叙事视角 | POV 是否越界，角色是否知道了不该知道的信息 |
| 风格连续 | 声口、叙事密度、类型节奏是否突然变成另一部作品 |

## 已有内容保留审核

当任务是“调整世界观、改主线、清空章节、重做大纲、删除旧设定、合并补充设定”时，先执行已有内容保留审核，再评价新设定质量。

必须检查：

- 是否读取并盘点了当前 `book.json`、`chapters.json`、章节正文文件和已有补充条目。
- 是否区分三类内容：章节规划 / 章节正文 / 世界设定。清空章节时不得连带删除世界设定内容。
- 是否保留或融合人物谱系、角色经历、世界组织、地图台账、怪物体系、战斗体系、伏笔账本和风格规则。
- 是否把与新方向冲突但仍有价值的设定降级为地方传闻、旧名、历史残留、黑市行话、待审项，而不是直接删除。
- 是否对每个删除项给出理由：重复、被用户否定、无法服务人物/地图/冲突、与新主线硬冲突。
- 是否把最终保留结果转成作品内稳定事实、风格边界或后续待补设定。不要把“本次调整的保留、降级、删除过程”原样写入 `memoryNotes`、书籍介绍或大纲指导。

内部审核输出建议附带：

```json
{
  "content_retention": {
    "preserved": [],
    "merged": [],
    "downgraded": [],
    "deleted": [],
    "needs_restoration": []
  }
}
```

这段 `content_retention` 只供审核报告、调试和人工 review 使用。若输出目标会写回 `intro / outlineGuide / extraIntroSections / storyAssets / narrativeState / chapters.summary`，必须把处理结果改写为作品内语言：

- 删除旧主线 -> 新主线以某人的行动、路线、关系或地方余波展开。
- 降级怪谈线 -> 奇异感来自自然风物、民俗传闻、旧路和人心。
- 排除宫廷斗争 -> 王朝以军镇、税路、关牒、供奉院、粮道和边防制度影响人物行路。
- 放弃天下第一终局 -> 终局落在具体承诺、技艺沉淀、关系结算、地方余波或继续生活。

若发现核心资产被整块覆盖，至少标为 P1；若人物谱系、地图、组织、怪物或战斗台账被误删导致后续长篇无法承接，标为 P0。

## 大地图与生态审核

遇到奇观地图、废土远征、战争路线或多势力长篇时，额外检查：

- 章节当前位置是否能从上一章合理抵达，路程、伤势、水粮和追兵压力是否成立。
- 新地图是否有明确覆盖范围、边界、相邻区域、资源点和控制势力。
- 奇观是否改变了角色行动，而不是只换了背景名。
- 世界组织是否在地图上有可见控制力：税、证件、巡查、关卡、配给、审判、代理人或民间称呼是否前后一致。
- 怪物是否和当地资源、气候、地貌、迁徙、繁殖或人类制度发生关系。
- 怪物生态是否有生态发动机：光、热、雾、盐、尸体、菌毯、矿尘或旧技术残留如何养活食物网。
- 物种是否形成谱系和食物网，而不是互不相干的单体怪物清单。
- 物种是否覆盖尺度矩阵：微型、小型、中型、大型、巨型 / 超大型、地貌级 / 群体级生命是否形成层次。
- 物种是否覆盖栖境矩阵：陆地、水域、空域、地下、建筑寄生、树冠、雾域或类人社会是否至少有多种可见存在。
- 物种体态是否过窄：是否过度依赖虫、蛛、菌、单体野兽，缺少鸟、鱼、软体、植物、矿物、气雾、群体或类人生命。
- 是否同时存在生产者、清道者、小型群居物、牧食 / 滤食者、捕食者、寄生 / 拟态者、生态工程者和关键种。
- 每个重要物种是否至少连接三个其他物种，并改变一个人类职业、价格、禁忌或路线。
- 人类势力是否利用当地风险获利，例如税路、路权、药棚、雇佣、撤离名额。
- 地缘关系是否能转化成任务、价码、冲突或选择，而不是停在说明。

如果有 `mapAtlas`，审核时必须核对 `chapter.mapRegionId / mapCoordinate / routeStage` 是否能在地图台账中找到对应区域。

## 战斗场面审核

遇到战斗、追逃、对峙、战争、怪物袭击或高潮场面时，额外检查：

- 战斗目标是否清楚，是否避免默认“杀死对方就是胜利”。
- 战斗职能是否来自生存工种或世界压力，而不是固定职业树。
- 空间是否动态变化：桥断、地陷、起雾、涨潮、光源变化、缺氧、承重变化、封路或人群改道是否影响打法。
- 时间压力是否明确：灯油、潮汐、药效、车次、封锁、援手、契约时限或怪物聚群是否逼角色提前选择。
- 感官压迫是否影响判断：声音、温度、呼吸、气味、光线、震动或重量是否改变角色行动。
- 错误是否有代价：点错灯、听错声音、走错一步、提前开火、忘记封味、没看风向、相信过期经验等是否改变局势。
- 对手是否会学习、反制、诱导或利用人的习惯，而不是只负责扑咬或惊讶。
- 失败是否改变后续世界状态：路线、资源、名声、债务、组织态度、人物关系、伤势、污染或通行权是否发生变化。
- 胜利是否带来余波，而不是一结束就清零。
- 战斗是否推动人物变化，例如第一次断后、第一次放弃某物、第一次救人后付出代价、第一次发现规则比敌人更可怕。

若核心战斗只靠技能名、爆发升级或主角临场开挂解决，至少标为 P1；若高潮战没有目标、代价、反制和余波，标为 P0。

## 命名与术语审核

命名问题不是单纯好不好听，还会影响世界可信度。需要检查：

- 是否过度复用同一前缀或同一构词模板。
- 同一阵营、职业、怪物、道具是否缺少历史和人文来源。
- 俗称、官称、技术名、禁忌名是否混乱或没有使用者。
- 怪物命名是否只有“X兽 / X虫 / X蛛 / X菌 / X者”这类统一后缀，缺少声音、痕迹、行为、材料、禁忌、商品名或职业行话来源。
- 重要怪物是否至少有俗名、行话和官名 / 旧名，并能看出谁这么叫、为什么这么叫。
- 重要名词首次出现是否通过行动、场景或关系解释，而不是孤立堆设定。

最小修复优先保留已有核心意象，只替换批量套壳、重复和缺乏来源的名字。

## 人物谱系审核

遇到长篇、多阵营、多文明或角色持续扩展时，额外检查：

- 重要角色是否归属明确谱系，例如血缘前史线、同行线、制度线、对手线、职业线、非人文明线。
- 角色是否有明确叙事必要性：可以改变剧情状态，也可以提供地方感、生活感、情绪停顿、价值对照或世界真实度；不能只负责解释设定、夸主角、送道具或制造一次性情绪。
- 重要角色是否像主角不在时也会继续生活：是否有日常生计、熟悉的人和地方、正在忍受的问题、害怕失去的东西。
- 抽象档案是否转成行为痕迹：目标、恐惧、秘密和债务是否通过习惯动作、口头禅、规避方式、空间选择、物件或身体记忆显出。
- 人物与地方是否绑定到身体习惯、称呼、交易、避讳和判断方式，而不是只写“来自某地”。
- 本章出场人物是否改变了至少一种状态，或让当前地点、制度、资源、怪物生态、阶层关系更像真实存在过。
- 角色秘密是否过早暴露，或长期不回收导致档案失效。
- 死者、失散者、记忆人物、非人角色的 `status` 是否清楚，避免后续误用。
- 关系推进是否跳级，例如互防角色突然无条件信任，制度人物突然无代价倒戈，对手突然只负责惊讶。
- 关系推进是否有小证据，例如共享小资源、目睹脆弱、没拆穿、替对方保留体面、默认留座、危险后仍留退路。
- 重要人物是否保留适当留白：传闻、旧物、矛盾证词、不愿解释的习惯是否被一次性讲空。

最小修复优先补一条谱系关系、一个生活痕迹、一个地方化习惯、一次关系小证据、一个可验证证据或修改关系状态，不要为了修人物而重写整条主线。

## 连续性审核优先级

审核时不要平均用力。优先级如下：

```text
阻断后续剧情的硬矛盾
> 用户明确要求保留的资产被破坏
> 人物动机和关系跳变
> 时间 / 空间 / 规则无法成立
> 伏笔承诺失效
> 风格和命名质感问题
```

连续性审核的目标不是把文本改成“最完美”，而是保护长篇能继续写。能用一处小补丁解决的，不做大重写；能通过补一条台账解决的，不强行改章节结构。

## 证据分级

审核结论必须区分证据强弱。

| 证据级别 | 定义 | 处理 |
|---|---|---|
| 明确证据 | 正文或 storyAssets 直接写明 | 可判定问题 |
| 强推断 | 多处信息共同指向 | 可标问题，但说明推断链 |
| 弱推断 | 只有单处暗示或读感 | 标为风险，不当成硬错误 |
| 信息不足 | 缺少上下文 | 写“无法确认”，提出需补资料 |

不要把“我觉得这样更好”写成 P0/P1。审美建议应降级为 P3，除非它导致类型承诺失败、人物动机断裂或后续无法承接。

## 时间线审核

时间线问题是长篇最常见的硬伤之一。

检查项：

- 事件先后：A 是否必须发生在 B 前，文本是否颠倒。
- 旅程耗时：距离、地形、交通工具、伤势、天气是否匹配。
- 恢复时间：伤口、疲劳、中毒、精神创伤是否恢复过快。
- 信息传播：消息从哪里传到哪里，需要多久，谁能提前知道。
- 制度流程：审判、考试、任命、运输、救济、通缉是否有时间成本。
- 季节与节日：农时、潮汐、迁徙、雪季、祭日是否一致。
- 年龄与经历：角色年龄是否足以经历已写事件。
- 同时性：同一角色是否出现在两个地点，或同一物品被两边使用。

最小修复：

- 改一处时间词：昨日、三日前、半月后。
- 补一句延迟原因：封路、等船、养伤、审查、雨季。
- 把“立刻知道”改成“通过线人 / 驿站 / 广播 / 祷告网 / 黑市账册知道”。
- 调整章节顺序或把某事件降级为传闻。

## 空间与路线审核

地图连续性要检查人物是否真的能到达。

检查项：

- 当前地点是否能从上一地点抵达。
- 路线是否经过受控区、禁区、怪物迁徙区或季节封路。
- 人物是否知道这条路，知道的来源是什么。
- 伤员、货物、孩子、囚犯、怪物材料是否会改变速度。
- 战斗场景中退路、遮挡、距离和高低差是否前后一致。
- 室内场景门窗、楼梯、走廊、邻房声音是否自洽。
- 同一地点在不同章节的布局是否发生无解释变化。

最小修复：

- 补路线代价：绕路、等船、雇向导、买路券、换装。
- 补认知来源：旧路歌、地图、当地人、旧账册、童年经历。
- 把不合理直达改成中转地或压缩为“几日后”。
- 在战斗中补一句方位锚点，让读者重新定位。

## 人物动机审核

动机问题比设定问题更伤读者信任。

检查项：

- 角色此刻知道什么，不知道什么。
- 角色最想要什么，最怕失去什么。
- 此行动是否符合他过去的创伤、利益、价值观和关系。
- 若行动反常，文本是否提供压力、诱因、误判或伪装理由。
- 角色是否为了推进剧情突然变笨、变善、变坏或变工具。
- 关系变化是否有小证据支撑。

最小修复：

- 补一句角色为什么现在必须这样做。
- 补一个外部压力：追兵、债务、限时、证据、伤者。
- 补一个内部触发：旧伤、羞耻、承诺、恐惧、误解。
- 把“无条件帮助”改成“交换条件 / 旧债 / 临时同盟”。
- 把突然信任改成有限信任：只交出部分信息，只同行一段路。

## 规则与能力审核

能力规则一旦破坏，战斗和爽点都会失去可信度。

检查项：

- 能力来源是否一致：血统、训练、器官、资源、契约、科技。
- 使用条件是否一致：距离、材料、冷却、代价、地形、情绪。
- 反制规则是否存在，是否被敌人合理利用。
- 上一章获得的能力是否被遗忘。
- 主角是否临时开挂解决核心问题。
- 弱点是否只在需要时出现，其他时候消失。
- 战力差是否能通过地形、策略、资源或代价弥补。

最小修复：

- 补使用代价或限制。
- 补前文铺垫，说明能力曾被训练或见过。
- 把胜利改成有限胜利：夺路、拖延、保住证据，而非击杀强敌。
- 让敌人学习一次，证明规则对双方都有效。

## 组织与制度审核

组织连续性不仅是名称一致，还包括权力如何运作。

检查项：

- 组织的管辖范围是否前后一致。
- 同一组织在首都、边地、荒野的控制力是否有距离衰减。
- 证件、税、考试、配给、审判、征召等制度是否有流程和成本。
- 内部派系是否突然消失或立场无解释变化。
- 组织惩罚是否前后轻重不一。
- 角色是否绕过制度却没有付出代价。
- 普通人是否会因为制度变化改变生活方式。

最小修复：

- 补代理人或地方例外。
- 补行贿、走私、熟人、临时通行、伪造文书的代价。
- 把组织反应延迟化：先登记、再追查、后封路。
- 补派系差异：不是组织变脸，而是另一派接手。

## 伏笔承诺审核

伏笔不是所有未解释信息。只有文本明显让读者期待后续回收的内容，才进入伏笔账本。

需要入账：

- 被重复强调的物件、地名、梦、伤痕、称呼。
- 角色异常回避的问题。
- 明显违反常识的规则例外。
- 未解释的能力、血统、旧债、救命恩。
- 章节结尾明确抛出的风险或选择。

不必入账：

- 氛围性细节。
- 一次性环境描写。
- 普通生活物件。
- 已在当前章完成作用的小线索。

审核伏笔时问：

- 它承诺了什么。
- 读者大概会期待何时回收。
- 回收后会改变什么状态。
- 如果不回收，是否会伤害信任。

## 风格连续性审核

风格问题通常不应高于 P2，但下列情况会影响长篇稳定：

- 同一角色声口突然变成另一个人。
- 章节类型承诺突然改变，例如严肃废土变成轻浮吐槽。
- 视角距离无理由跳变，读者不知道跟随谁。
- 命名系统突然换风格，像另一套世界观。
- 设定解释密度突然暴涨，剧情停住。
- 高潮后没有余波，长期代价被清零。

最小修复：

- 提取上一章角色声口规则，改当前章关键对白。
- 把解释段拆进行动、账册、对话和场景。
- 补过渡段说明情绪温度为什么变化。
- 把突兀命名改成同一体系内的俗名、官名或旧名。

## 审核输出写法

好的审核输出要像工程 bug report：

- 有证据：指出哪段信息与哪段冲突。
- 有影响：说明会导致读者误解、后续断裂还是设定失效。
- 有最小修复：给可直接改写的一句话、一个台账补丁或一个章节顺序建议。
- 有记忆更新：哪些内容要写回 `storyAssets`。

避免：

- “这里不够精彩”但不给原因。
- “建议重写整章”但没有定位硬矛盾。
- “人物不合理”但不说明动机链哪里断。
- “世界观不够完整”但不指出哪个规则无法支撑剧情。

## 回归检查

修完后要再检查一次：

- 修复是否引入新矛盾。
- 新增解释是否过度扩大世界观。
- 修改是否破坏用户明确保留项。
- 章节钩子是否仍成立。
- 后续大纲是否需要同步调整。
- `storyAssets` 是否记录新事实、角色状态、规则和伏笔状态。

连续性审核不是一次性挑错，而是让长篇资产持续可承接。

## 严重级别

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 阻断剧情或直接自相矛盾 | 必须修，不能只备注 |
| P1 | 大部分读者会注意到，影响可信度 | 优先修，给最小改法 |
| P2 | 影响清晰度或承接，但不阻断阅读 | 可修订或写入后续注意 |
| P3 | 可提升质感的建议 | 只在不干扰主线时处理 |

## 输出格式

```json
{
  "issues": [
    {
      "severity": "P1",
      "category": "timeline",
      "issue": "",
      "evidence": "",
      "impact": "",
      "minimal_fix": "",
      "memory_update": ""
    }
  ],
  "safe_to_publish": false,
  "required_memory_updates": []
}
```

## 最小修复原则

- 优先改局部句子、补一句因果、调整称谓或更新时间，不重写整章。
- 若正文已经很好，只修矛盾，不借审核名义改风格。
- 若有多个可选解释，选择对后续剧情牵连最小的解释。
- 修复后同步 `storyAssets`：角色状态、时间线、伏笔、规则和新增禁忌。

## 伏笔账本

伏笔条目建议包含：

```json
{
  "id": "",
  "seed": "",
  "plantedAt": "",
  "expectedPayoff": "",
  "payoffWindow": "",
  "status": "open",
  "risk": ""
}
```

审核时要区分：

- 未回收但仍在合理窗口内：记录提醒，不算错误。
- 已经错过承诺窗口：标为 P1 或 P2。
- 回收方式和埋设内容不对应：标为 P1。
- 回收后没有改变局势：提示加强后果。

## 常见失败

- 只检查错别字，忽略战力、关系和时间线。
- 把读者不知道的信息当成角色也知道。
- 修复时添加新设定，反而制造更大的规则债。
- 忘记把审核结论写回结构化连续性资料。
- 对“风格不喜欢”给 P0，混淆审美建议与硬矛盾。
