# Character Lineage Reference

`character-lineage` 用于设计故事中的人物谱系和角色档案。它的目标不是做一张名单，而是让人物辅助推动故事、穿针引线、制造压力、承接伏笔，并在长篇里保持功能稳定。

## 核心目标

人物设计时必须回答：

- 这个人从哪里来。
- 他和其他人是什么关系。
- 他在故事里出现几次，分别推动什么。
- 他的身份、经历、秘密和结局如何影响主线。
- 他改变了主角的哪种状态：目标、资源、关系、身份、信息差、地图可达性、规则理解或代价。

不要只写“他是谁”。应详略得当地写清身份、重要经历、故事重点、关系变化和结局方向。

## 人物谱系先于人物表

先按谱系组织人物，再补单人档案。谱系说明一组人物共同承担什么叙事功能。

常见谱系：

| 谱系 | 功能 |
|---|---|
| 血缘 / 前史线 | 解释主角性格来源、旧伤、旧物、原生关系和后置真相 |
| 同行 / 伙伴线 | 测试信任边界、资源交换、救急、误会、背叛和共同成长 |
| 对手 / 压制线 | 建立被低估、被利用、被定价、被误解和反夺价码 |
| 制度 / 权力线 | 把抽象规则变成人、账册、职位、命令、门槛和惩罚 |
| 职业 / 技术线 | 让战斗体系、工艺、医救、斥候、交易、旧械等能力人格化 |
| 地缘 / 阵营线 | 体现不同地区、阶层、族群、城市和组织之间的利益差异 |
| 非人 / 文明线 | 让怪物、异族、神灵、AI 或异星文明拥有工种、等级、禁忌和族群目的 |
| 情感 / 价值线 | 让主角面对爱、亏欠、救赎、尊严、选择和不可回头的承诺 |

每条谱系至少要有：核心人物、叙事功能、对主角施加的压力、关系推进规则。

## 谱系 Schema

```json
{
  "characterLineage": [
    {
      "id": "",
      "lineage": "",
      "coreCharacters": [],
      "storyFunction": "",
      "pressureOnProtagonist": "",
      "relationshipRules": [],
      "firstAppearanceWindow": "",
      "payoffWindow": "",
      "risk": ""
    }
  ]
}
```

如果项目存储结构没有独立 `characterLineage` 字段，可把谱系写入 `storyAssets.relationships / worldview / memoryNotes`，把单人档案写入 `storyAssets.characters`。

## 角色档案 Schema

重要角色建议使用：

```json
{
  "id": "",
  "name": "",
  "aliases": [],
  "namingOrigin": "",
  "addressRules": [],
  "lineage": "",
  "role": "",
  "publicIdentity": "",
  "origin": "",
  "briefHistory": "",
  "importantExperiences": [],
  "goal": "",
  "fear": "",
  "secret": "",
  "debt": "",
  "resourceOrLeverage": "",
  "narrativeFunction": "",
  "relationshipState": "",
  "relationships": [],
  "firstAppearancePlan": "",
  "majorAppearances": [],
  "endingDirection": "",
  "growthArc": "",
  "taboos": [],
  "status": "active | memory | dead | missing | unconfirmed | nonhuman"
}
```

字段解释：

- `origin`：人物来历，必须能影响声口、技能、恐惧或立场。
- `namingOrigin`：姓名来源，说明它与地域、阶层、家族、职业、时代或族群语言的关系。
- `addressRules`：称呼规则，说明谁叫本名、谁叫外号、谁叫官称、谁不能直呼。
- `briefHistory`：简单经历，只写和主线有关的部分。
- `importantExperiences`：重要经历，优先写能回收成冲突或证据的事件。
- `narrativeFunction`：他在故事中负责推动什么，不要写成“重要配角”。
- `majorAppearances`：略写出场节点，每次出场都要有目的。
- `endingDirection`：结局方向，不必剧透细节，但要知道他最终承担什么后果。
- `status`：状态要清楚，避免死者、失散者、记忆人物或非人角色被误当普通在场人物。

## 角色命名技巧

角色命名应像世界的一部分，而不是随机好听的标签。命名前先确认人物所属文化、地域、阶层、家族、职业、时代和语言习惯。

常用方法：

- 地域来源：边地、港口、山城、学院、旧都、荒村的人名可以有不同音节、字感和称呼习惯。
- 家族来源：姓氏、辈分、继承名、收养名、弃名、婚后名能体现关系和旧账。
- 阶层来源：贵族全名长，平民常用短名，军队和行会常用编号、职称或绰号。
- 职业来源：医师、猎人、巡检、船工、祭司、商人可能拥有行业称呼。
- 历史来源：战后改名、避讳、纪念死者、抹去旧姓，都能带出背景。
- 非人来源：人类给怪物的他称、怪物自称、学者分类名和交易名可以互相冲突。

一个重要角色可拥有多层称呼：

| 称呼 | 作用 |
|---|---|
| 本名 | 最稳定的身份标记，不一定所有人都能直呼 |
| 乳名 / 小名 | 暴露亲密关系、旧时光或被轻视的状态 |
| 外号 | 来自战绩、缺陷、职业、误会或民间传闻 |
| 官称 / 职称 | 体现制度位置，如巡检、司库、祭司、导师 |
| 代号 | 适合秘密组织、军队、实验体、情报线 |
| 禁忌名 | 不能直说的真名、旧名、罪名或被抹去的名字 |
| 敌方称呼 | 暴露偏见、恐惧、蔑视或政治立场 |

称呼会随关系推进变化。陌生人叫官称，伙伴叫短名，旧敌叫旧名，亲人叫乳名，制度人物坚持叫编号，都能比旁白更快说明关系状态。

命名注意：

- 避免同一批角色同声母、同字头、同尾音或同模板，读者会混淆。
- 幻想故事不要堆罕见字；可为每个地区建立命名池，让名字有统一来源但不重复。
- 重要角色名字要易读、可记、有区分度；生僻设定名可留给地名、古物或仪式。
- 角色名字不要全部围绕同一核心意象。世界里的人会按家族、职业、地方、信仰和交易习惯命名。
- 若名字本身承载秘密，先设计公开称呼，再设计真名暴露的时机和后果。

## 角色功能

一个角色至少应承担一种功能：

- 给主角一个目标。
- 抢走或提供一种资源。
- 暴露一条规则。
- 挑战主角价值观。
- 让主角付出代价。
- 带来一条地图路线。
- 揭示一个秘密的证据载体。
- 推动一种关系变化。
- 让世界观从抽象规则变成具体压力。

若角色没有功能，应合并、删除或改成背景称呼。

## 出场设计

角色第一次出场不要先写履历。优先让他带着动作、任务、资源、压迫或选择入场。

有效首次出场：

- 他正在做一件能显示身份的事。
- 他掌握主角需要的资源。
- 他制造或解决一个具体障碍。
- 他让主角产生误判。
- 他用一句话或一个动作暴露关系边界。

无效首次出场：

- 大段介绍姓名、外貌、身份和履历。
- 只负责解释世界观。
- 只负责赞美或衬托主角。
- 没有带来状态变化。

## 关系推进

人物关系必须有阶段，不要跳级。

常见关系阶段：

```text
陌生 -> 试探 -> 交易 -> 有限信任 -> 欠债 -> 冲突 -> 选择 -> 破裂或稳固
```

每次关系推进都要有证据：救过一次、骗过一次、付过一次债、共同承担一次代价、保守过一个秘密、公开反对过一次制度。

关系不能只靠旁白宣布“他们更信任了”。要让读者看到行为变化：称呼改变、距离改变、资源共享、秘密暴露、退路开放、背后不再设防或重新设防。

## 角色经历与结局

角色档案要略写他的故事路径：

- 出身或来历。
- 进入主线的原因。
- 与主角第一次发生关系的节点。
- 中段重要选择或背叛。
- 高潮中承担的代价。
- 结局方向：存活、死亡、失踪、离队、掌权、流放、和解、清账、成为新秩序的一部分。

结局方向要服务主题，不要为了煽情随意牺牲角色。角色死亡必须改变局势、关系或价值判断。

## 非人角色

怪物、异族、神灵、AI、异星文明或器物人格也需要角色档案。它们不应只是攻击单位。

非人角色额外考虑：

- 族群目的。
- 社会等级或工种。
- 交易方式或交流方式。
- 禁忌和价值观。
- 与人类的误解。
- 它如何推动主角重新理解世界。

## 审核清单

完成人物谱系和角色档案后检查：

- 是否先有谱系，再有角色。
- 每条谱系是否有叙事功能和关系推进规则。
- 每个重要角色是否有来历、经历、秘密、关系和结局方向。
- 角色是否能改变至少一种故事状态。
- 角色命名是否体现地域、阶层、家族、职业或称呼关系，是否避免同模板堆名。
- 是否有角色只负责解释设定、送道具或夸主角。
- 关系是否跳级，秘密是否过早暴露。
- 死者、失散者、记忆人物和非人角色的 `status` 是否清楚。
- 人物是否和地图、制度、资源、怪物生态或战斗体系发生联系。
